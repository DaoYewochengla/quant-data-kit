# quant-data-kit

> 把 A 股 / 可转债 / ETF 的公开行情数据，干净地落到你本地。
> **纯数据工程工具。不含任何策略、因子、选股规则、买卖建议。**

## 这个项目解决什么问题

做量化研究，前 80% 的时间不是花在策略上，是花在**数据**上：

- **接口悄悄变了**。AKShare 的 `bond_zh_hs_cov_daily` 依赖的新浪 `klc_kl.js` 已经 404 下线，
  调用它只会得到一个 `KeyError`；而更多时候接口返回**空 DataFrame 却不报错**，
  你的脚本默默把空数据写进磁盘，等你发现的时候模型已经用脏数据训练完了。
- **增量更新是个陷阱**。"文件存在就跳过"会导致永久断更；"每次都全量重拉"在几千个标的
  面前完全不可行。而不记录最后交易日，你根本不知道漏了哪几天。
- **单一数据源不可靠**。东财是境内接口，但在配了系统代理的机器上会被送到代理，
  表现为**间歇性 ProxyError** —— 同一个接口一会儿通一会儿不通，极难排查。
- **幸存者偏差**。个股有退市、转债有强赎，只用"当前还活着"的标的回测，
  收益率会凭空多出十几个点。而退市股名单和现存股名单来源还不同，
  任一拉取失败就会让结果**严重失真**。

`quant-data-kit` 把这些脏活封装好：**一次配好，天天增量，数据有问题会明确告诉你。**

## 它做什么 / 不做什么

| ✅ 做 | ❌ 不做 |
|---|---|
| 拉取公开行情数据（东财/新浪/腾讯/同花顺公开接口） | 不含任何选股逻辑 |
| 增量更新、断点续传、多源自动切换 | 不含任何因子参数、权重 |
| 数据完整性检查（缺口、空值、异常跳变、重复） | 不含任何回测框架 |
| 退市股 / 已摘牌转债的存档（防幸存者偏差） | 不提供任何投资建议 |
| 标准化的列名与表结构，多源统一 | 不提供任何信号、预测、择时 |

## 快速开始

```bash
# 初始化本地数据目录
qdk init --data-dir ./data

# 首次全量拉取（可转债 / 个股 / ETF）
qdk fetch --type cb,stock,etf --start 20180101 --data-dir ./data

# 每日增量（推荐挂定时任务）
qdk update --type cb,stock,etf --data-dir ./data

# 体检：看看有没有漏交易日、空数据、异常值
qdk check --type cb,stock,etf -v --data-dir ./data

# 查看可用类别与各源优先级
qdk info
```

调试时用 `--limit N` 抽样若干标的（**按代码随机抽样，不是取头部**——
名单是按代码升序的，取头部只会拿到一批尚未上市或刚退市、只有 1 行数据的标的）：

```bash
qdk fetch --type cb --limit 10 --start 20240101 -v
```

## 数据源优先级（实测）

各源可用性随网络环境与时间变化，本工具按优先级自动降级。
以下为 2026-09 在**配了系统代理的 Windows** 环境下的实测结果：

| 类别 | 优先级 | 实测情况 |
|---|---|---|
| 可转债 | 腾讯 → 新浪 | 腾讯可用；新浪 `klc_kl.js` 已下线 |
| 个股 | 腾讯 → 新浪 → 东财 | 腾讯可用；新浪可用但需分页（约 13 秒 / 5500 只） |
| ETF | 腾讯 → 新浪 | 腾讯可用 |

**关于代理**：境内数据源不应走代理。本项目所有 HTTP 请求均显式 `trust_env=False`，
不受系统代理影响。如果你确实需要走代理访问，请自行传入 `proxies`。

## 为什么值得用

### 绝不静默成功

AKShare 在节假日、标的停牌、接口变更时都会返回空 DataFrame 而不报错。
本项目对空结果一律抛 `EmptyResult`，由调用方决定是"跳过"还是"报错"。

**一个写进磁盘的空文件，比一个报错危险得多。**

### 原子写入 + 增量去重

- 先写 `.tmp` 再 `os.replace`。直接覆盖写时若进程被杀，会留下半截文件，
  而下次运行会把它当成"已有数据"跳过 —— 脏数据就此固化。
- 增量合并按 `date` 去重（保留最新写入的），因此**重复运行是幂等的**：
  已验证连续两次 `update` 后，成功 0 / 跳过 10 / 失败 0。

### 拒绝写入任何空数据（双保险）

即使 DataFrame 非空，只要日期列解析后全部无效，也会被拒绝——
否则会落盘成一个只有表头的文件，伪装成正常数据。

### 已退市标的不会被无限重拉

名单标注为"现存"但数据已长期停滞的标的（提前强赎、暂停上市），
若不做识别会造成同一批死标的被每次增量无限重拉。
本工具对 180 天无新数据的标的自动停止重拉。

### 分页拉取，绕过静默上限

腾讯 K 线接口的 `datalen` 给太大（如 10000）会被**拒绝且不报错**——
返回 `code=0` 但 `data` 为空，表现为"该标的有数据却拉不到"。
本工具用分页回溯的方式拉取完整历史（实测单只可达 1279 根日线）。

## 数据体检

大多数人死在"数据悄悄坏了却不知道"。`qdk check` 覆盖五类问题：

| 检查项 | 说明 |
|---|---|
| 覆盖缺口 | 某标的最新交易日落后全市场最新交易日超过 N 天（漏跑 / 断更） |
| 空值 | 关键列存在 NaN |
| 价格异常 | 单日涨跌幅超阈值（未复权导致的跳变、数据源错位） |
| 重复行 | 同一日期出现多行 |
| 行数过少 | 疑似只拉到部分历史 |

```bash
$ qdk check --type cb -v
[cb] 检查 10 个标的
  全市场最新交易日: 2026-09-21
  ⚠️  数据滞后: 5 个
    [warn] 数据滞后 113020: 最新数据 2020-11-26，落后 2125 天
    [warn] 数据滞后 113619: 最新数据 2024-11-27，落后 663 天
```

## 挂定时任务

Linux / macOS（crontab）：

```cron
# 每个工作日 18:00 增量更新并体检
0 18 * * 1-5 cd /path/to/project && qdk update --type cb,stock,etf && qdk check --type cb,stock,etf
```

Windows（任务计划程序）：

```bat
"D:\path\to\python.exe" -m qdk.cli update --type cb,stock,etf --data-dir D:\data
```
